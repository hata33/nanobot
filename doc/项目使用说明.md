# nanobot 使用说明

> 面向使用者的快速指引：它是什么、能干什么、怎么上手。

---

## 1. 它能做什么？

nanobot 把"大语言模型 + 工具 + 多平台消息"打包成一个可运行的 Agent 服务：

- **多端对话**：一条消息可来自 CLI、WebUI、Telegram、Discord、Slack、飞书、钉钉、QQ、微信、企业微信、Email、Matrix、WhatsApp、WebSocket 等渠道，统一走 Agent 核心处理。
- **持久化记忆**：自动保存会话历史，支持长期记忆（Dream 整合），断线重连后仍能延续上下文。
- **工具生态**：开箱即用的文件读写、Shell 执行（带沙箱）、Web 搜索 / 抓取、MCP 服务器接入、定时任务、图片生成、子 Agent 派发、自我修改能力。
- **模型无关**：支持 OpenAI / Anthropic / Azure / Bedrock / GitHub Copilot / Codex / Ollama / LiteLLM 等数十种后端，配置即切换。
- **可扩展**：自定义 Skill、Tool、Channel 都有插件机制，无需改核心代码。

---

## 2. 实现效果

使用 nanobot 后，你可以：

- 在任意已接入的聊天平台，直接与具备"工具使用能力 + 长期记忆"的 AI 助手对话。
- 让助手自动读写文件、执行代码、搜索网页、定时提醒、生成图片、调度子任务。
- 多用户/多租户隔离：每个会话独立上下文，Workspace 级文件访问控制。
- 服务化部署：通过 `nanobot gateway` 启动完整服务，WebUI 提供现代聊天界面，同时暴露 OpenAI 兼容 API。

## 3. 如何使用

### 3.1 环境准备

- Python 3.11+
- Node.js / Bun（如需开发 WebUI）

### 3.2 安装

```bash
# 克隆仓库
git clone https://github.com/your-org/nanobot.git
cd nanobot

# Python 依赖
pip install -e .

# WebUI 开发（可选）
cd webui && bun install
```

### 3.3 配置

编辑 `~/.nanobot/config.json`，至少设置一个 Provider 和 API Key：

```json
{
  "agents": {
    "defaults": {
      "provider": "openai",
      "model": "gpt-4o"
    }
  },
  "providers": {
    "openai": {
      "apiKey": "sk-..."
    }
  }
}
```

### 3.4 快速运行

```bash
# CLI 单轮对话
nanobot agent -m "你好"

# 交互式 CLI
nanobot agent

# 启动 Gateway（含 WebUI 和全部渠道）
nanobot gateway
```

启动后访问：
- WebUI：`http://127.0.0.1:8765`
- 健康检查：`http://127.0.0.1:18790/health`

### 3.5 常用命令

```bash
# 查看帮助
nanobot --help

# 查看配置
nanobot config show

# 重启 Gateway
nanobot restart
```

### 3.6 扩展开发

| 想扩展什么 | 怎么做 |
|---|---|
| 新聊天渠道 | 实现 `BaseChannel`，参考 `channels/` 现有实现 |
| 新工具 | 在 `agent/tools/` 下新增模块，或通过 entry point 插件 |
| 新模型后端 | 继承 `LLMProvider`，在 `providers/` 实现并注册 |
| 自定义 Skill | 在 `workspace/skills/` 或 `nanobot/skills/` 下写 `SKILL.md` |
