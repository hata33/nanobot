# 核心执行链路与架构速览

> 站在项目源码视角，速览 nanobot 的一次消息流转、模块职责与关键架构决策。

---

## 1. 一句话定位

nanobot 是一个轻量级开源 AI Agent 框架，用异步消息总线解耦"多端消息接入"与"LLM 执行循环"，让一次用户输入能在统一管道里完成上下文构建、工具调用、记忆持久化，并以最小耦合方式适配多种聊天平台与模型后端。

---

## 2. 骨架调用图

一次最简完整执行（以 CLI 或 WebUI 单条消息为例）：

```text
cli/websocket_channel.send(message)
├─→ MessageBus.publish_inbound(InboundMessage)
│
├─→ AgentLoop.run_turn(msg, session)
│   ├─→ SessionManager.get_or_create(session_key)
│   ├─→ ContextBuilder.build(messages, workspace, skills)
│   ├─→ AgentRunner.run(spec)
│   │   ├─→ provider.chat(messages, tools)
│   │   ├─→ tool_registry.get(name)
│   │   ├─→ tool.execute(args, context)
│   │   └─→ （循环：provider → tool → provider → ...）
│   ├─→ Memory.consolidate(...)          # 异步 / 定时
│   └─→ SessionManager.save_turn(...)
│
└─→ MessageBus.publish_outbound(OutboundMessage)
    └─→ channel.deliver(response)
```

核心要点：`AgentLoop` 管"会话侧"，`AgentRunner` 管"模型侧"；两者通过 `RunSpec` / `TurnContext` 交接，不互相侵入。

## 3. 模块职责速查表

| 模块 | 一句话职责 | 关键接口 / 抽象 | 架构模式 |
|---|---|---|---|
| `bus/queue.py` | 异步队列，解耦通道与 Agent | `MessageBus.publish_inbound / consume_inbound / publish_outbound / consume_outbound` | 发布-订阅 / 队列 |
| `channels/` | 多平台接入，把外部消息转为 InboundMessage | `BaseChannel`、`ChannelManager`、`publish_inbound` | 策略 + 工厂 |
| `agent/loop.py` | 单次消息的编排入口，管 session、context、hooks、输出 | `AgentLoop.run_turn`、`TurnState` | 状态机 |
| `agent/runner.py` | LLM 对话循环：发消息、收 tool call、执行工具、重试 | `AgentRunner.run`、`AgentRunSpec` | 模板方法 / 迭代器 |
| `providers/` | 把统一调用映射到不同 LLM 后端 | `LLMProvider.chat`、`ProviderFactory.create` | 策略 + 工厂 |
| `agent/tools/` | 把工具能力注册并暴露给模型 | `ToolRegistry`、`BaseTool.execute` | 注册表 |
| `session/manager.py` | 会话历史读写、TTL 压缩、继续标记 | `SessionManager.get_or_create / save_turn / compact` | 仓储 |
| `agent/memory.py` | 长期记忆与 Dream 二阶段整合 | `Consolidator.run`、`MemoryStore` | 观察者 / 批处理 |
| `config/schema.py` | Pydantic 配置模型，camelCase / snake_case 兼容 | `Config`、`AgentDefaults`、`ProviderConfig` | 配置对象 |
| `command/router.py` | 斜杠命令路由 | `CommandRouter.dispatch` | 责任链 |
| `webui/` | 前端 SPA，通过 WebSocket 与 Gateway 通信 | `GatewayServices`、`NanobotClient` | 客户端-服务端 |

## 4. 核心设计决策

1. **消息总线解耦通道与 Agent**
   用 `MessageBus` 的 inbound/outbound 队列把"谁发的消息"与"怎么处理消息"彻底分开，新增一个聊天平台只需实现 `BaseChannel` 并调用 `publish_inbound`，不需要改动 Agent 核心。

2. **Loop / Runner 职责二分**
   `AgentLoop` 管 session、workspace、context、outbound；`AgentRunner` 管 provider 调用、tool 循环、streaming 与重试。边界清晰，调试时可按"会话问题找 Loop，模型/工具问题找 Runner"快速定位。

3. **Provider 抽象 + 注册表**
   所有 LLM 后端统一继承 `LLMProvider`，通过 `ProviderFactory` + `ProviderRegistry` 按配置、API Key、base URL 自动选择。新增后端只需加一个 Provider 实现和一个 schema 字段，不侵入调用方。

4. **工具即插件，按需发现**
   工具目录 + entry point 双路发现，`ToolRegistry` 统一管理。工具签名即模型契约，`tool.execute(args, context)` 是唯一定点，前端/模型侧看到的始终是同一份 schema。

5. **Session 与 Memory 分层持久化**
   Session JSONL 保存近期对话；`MEMORY.md` + `history.jsonl` 做长期记忆；Dream 任务异步做两阶段整合。时间维度分得清楚，避免"近期上下文"和"长期知识"互相污染。

## 5. 最简示例运行路径

```python
import asyncio
from nanobot.bus.queue import MessageBus
from nanobot.agent.loop import AgentLoop
from nanobot.session.manager import SessionManager
from nanobot.config.schema import Config

cfg = Config()  # 默认配置指向 ~/.nanobot/config.json
bus = MessageBus()
sessions = SessionManager(cfg)

async def main():
    loop = AgentLoop(bus, sessions, cfg)
    # 1) 发布一条用户消息
    await bus.publish_inbound(InboundMessage(
        channel="cli", session_key="user-1", text="你好"
    ))
    # 2) Loop 消费、Runner 执行、Session 落盘
    await loop.start()
    # 3) 消费返回结果
    out = await bus.consume_outbound()
    print(out.content)

asyncio.run(main())
```

对应骨架图节点：
- `publish_inbound` → `AgentLoop.run_turn` → `SessionManager.get_or_create` → `AgentRunner.run` → `SessionManager.save_turn` → `publish_outbound`
